# موقع القرآن الكريم

تطبيق ويب لقراءة القرآن الكريم في المتصفح، أُعيد بناؤه بالاستفادة من مشروع
[Quran for Android](https://github.com/quran/quran_android) مفتوح المصدر.

**جاهز للنشر على GitHub Pages مباشرة**: ملفات ساكنة بالكامل، بلا build،
وبلا أي تبعية npm.

```
node server.mjs        # ثم افتح http://127.0.0.1:5173/
```

---

## المزايا

| الميزة | المسار |
|--------|--------|
| فهرس السور الـ١١٤ (بحث وتصفية فورية) + فهرس الأجزاء الثلاثين | `#/` |
| قراءة آية بآية بالنص العثماني مع رقم كل آية | `#/sura/2` |
| رابط مباشر لأي آية | `#/sura/2?ayah=255` |
| المصحف المدني بالصور (٦٠٤ صفحات) مع تقليب باللمس/الأسهم | `#/page/604` |
| ترجمة/تفسير بجانب كل آية، وأكثر من ٤٤٠ إصدارًا في عشرات اللغات | `#/settings` |
| بحث في النص كاملًا مع تجاهل التشكيل وبحث بالبادئة (`الرحم` ← الرحمن/الرحيم) | `#/search` |
| علامات للآيات وللصفحات + وسوم + تصدير/استيراد JSON | `#/bookmarks` |
| تلاوة صوتية: آية بآية، سورة كاملة، تكرار، وبار تلاوة ثابت | أي صفحة |
| متابعة آخر موضع قراءة، وسجل الصفحات المقروءة | `#/` |
| ثلاثة مظاهر (نهاري/ليلي/ورقي)، تحكم بحجم الخط، وطباعة نظيفة | `#/settings` |
| قراءة دون إنترنت بعد تنزيل النص مرة واحدة (IndexedDB) | `#/settings` |
| عارض للتوثيق داخل التطبيق | `docs.html` |

## التشغيل محليًا

```bash
node server.mjs                 # المنفذ 5173
node server.mjs --port 8080     # منفذ آخر
```

`file://` لا يعمل مع ES Modules في معظم المتصفحات، لذلك يلزم خادم — والخادم
المرفق بلا أي تبعيات (`server.mjs`).

## الأوامر

```bash
npm start      # تشغيل الخادم المحلي
npm test       # ٩٩ اختبار وحدة (بلا تبعيات)
npm run verify # يبدأ الخادم ويزحف شجرة الاستيراد للتأكد من سلامة كل المسارات
npm run check  # test + verify
```

## النشر على GitHub Pages

الدليل الكامل خطوة بخطوة — بما في ذلك ربط نطاق مخصّص لاحقًا — في
[`docs/DEPLOY-GITHUB-PAGES.md`](docs/DEPLOY-GITHUB-PAGES.md). الملخص:

1. أنشئ مستودعًا عامًا باسم **بحروف إنجليزية** (مثل `quran-web-v1`).
2. ارفع **محتويات** مجلد `quran-web-v1` إلى الجذر (`index.html` في المستوى الأول).
3. **Settings → Pages → Source: Deploy from a branch → `main` / `/ (root)`**.
4. بعد دقيقة أو دقيقتين يصبح الموقع على
   `https://<اسم-حسابك>.github.io/<اسم-المستودع>/`.

**أسماء الملفات والمجلدات كلها إنجليزية** (المحتوى نفسه عربي بالطبع)، لأن
المسارات العربية تُرمَّز عند الرفع أو الضغط فتُفشل العملية. هذا محمي باختبار
آلي: `tests/file-names.test.mjs` يفحص كل مسار في المشروع بما فيه اسم المجلد
نفسه.

المشروع يتضمن `404.html` (لتحويل أي مسار خاطئ إلى التطبيق) و`.nojekyll`
(لمنع معالجة Jekyll) وكل المسارات نسبية، فيعمل داخل مسار فرعي بلا أي تعديل.

## البنية

```
index.html                هيكل التطبيق (RTL) وحاويات الصفحة
docs.html                 عارض التوثيق
404.html                  تحويل المسارات غير الموجودة
server.mjs                خادم ملفات ثابتة بلا تبعيات (للتطوير فقط)
src/
  main.js                 التوصيل: المخزن، البيانات، المشغل، الموجّه، المظهر
  docs-viewer.js          منطق عارض التوثيق
  core/
    quran-info.js         حسابات الصفحة/الجزء/السورة (مكافئ QuranInfo)
    arabic.js             تطبيع النص العربي والبحث والتظليل
    markdown.js           مُحوِّل Markdown مصغّر للتوثيق
    store.js              العلامات والوسوم وآخر قراءة والإعدادات
    storage.js            تجريد localStorage مع بديل في الذاكرة
    router.js             موجّه hash بلا تبعيات
    dom.js  emitter.js    أدوات صغيرة
  data/
    surahs.js             البيانات الوصفية للسور (لقطة مرفقة)
    api.js                نص القرآن + التخزين المؤقت + إصدارات بديلة
    translations.js       الترجمات والتفسير من كتالوج الإصدارات
    audio.js              الروابط والمشغّل وقائمة التشغيل
    cache.js              غلاف IndexedDB
  features/               صفحات الواجهة (فهرس، آيات، مصحف، بحث، علامات، إعدادات، بار صوت)
  styles/main.css         كل الأنماط (سمات عبر متغيرات CSS)
tests/                    مشغّل اختبارات بلا تبعيات + بدائل وهمية + تحقق HTTP
docs/                     مصادر البيانات، النشر، الترحيل، استراتيجية الاختبار
```

## البيانات: قرار معماري مقصود

كل مصادر البيانات **ملفات ساكنة على CDN مسموح بـ CORS**، بلا مفاتيح ولا
مصادقة ولا خادم خلفي:

* نص القرآن والترجمات والتفسير: كتالوج إصدارات `quran-api` عبر jsDelivr.
* صور المصحف: `sufone/medina-mushaf` عبر jsDelivr.
* التلاوات: everyayah.com.

**لا يوجد أي اعتماد على `api.quran.com`** لأنه أُهمل، وبديله الرسمي يتطلب OAuth2
بمفتاح سري على خادم خلفي — وهو ما لا يمكن لموقع ساكن على Pages استخدامه
(الوثائق الرسمية تمنع استخدام مسار المتصفح للـ Content). التفاصيل والتحقق
والرخص في [`docs/DATA_SOURCES.md`](docs/DATA_SOURCES.md).

## كيف استُفيد من مشروع أندرويد

الملفات الأصلية كانت طبقة إعداد Gradle/Android (لا شيفرة تطبيق ولا بيانات).
لذلك طُبِّق **ترحيل** لا نسخ: ما يخص أندرويد أُسقط، وما ينفع في الويب نُقل
وأُعيدت صياغته، والمفردات المعمارية للمشروع الأصلي وُجِّهت إلى وحدات ويب مكافئة
(`common:data` → `src/data/`، `common:search` → `src/core/arabic.js`،
`feature:linebyline` → قارئ الآيات، `pages:madani` → قارئ المصحف).

التفاصيل الكاملة في [`docs/MIGRATION-FROM-ANDROID.md`](docs/MIGRATION-FROM-ANDROID.md).

## الاختبارات

المنهجية موروثة من المشروع الأصلي: **اختبر السلوك لا التنفيذ**، و**بدائل وهمية
بدل الـ mocks**، واختبارات سريعة وحتمية، وبنية Arrange/Act/Assert.
الأدوات أُعيد توجيهها إلى مشغّل Node بلا تبعيات، مع تحقق HTTP يزحف شجرة
الاستيراد كاملة — التفاصيل في [`docs/TESTING.md`](docs/TESTING.md).
