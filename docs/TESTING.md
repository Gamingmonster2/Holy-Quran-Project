# استراتيجية الاختبار — موقع القرآن الكريم

مُكيّفة من `TESTING_STRATEGY.md` الأصلي في Quran for Android. **المبادئ** حُفظت
بروحها كما هي، و**الأدوات** أُعيد توجيهها: Robolectric وKover وTurbine
وSQLDelight وMockWebServer لا وجود لها في المتصفح، وهذه البيئة بلا وصول إلى
مستودع الحزم أصلًا — لذلك المشغّل مكتوب يدويًا وبلا أي تبعية.

## الفلسفة (كما هي)

1. **اختبر السلوك لا التنفيذ** — تحقّق من المدخلات والمخرجات، لا من الحالة الداخلية.
2. **بدائل وهمية (fakes) بدل الـ mocks** — البديل الحقيقي ينجو من إعادة الهيكلة، والـ mock يوثّقها بدلًا من ذلك.
3. **سريع وحتمي** — كل اختبار أقل من ٥٠ مللي ثانية، ولا ترتيب إجباري بين الاختبارات.
4. **بنية حقيقية قدر الإمكان** — اختبر المخزن على تخزين وهمي حقيقي، لا على mock.

## الأدوات (مُعاد توجيهها)

| في أندرويد | المكافئ هنا |
|------------|--------------|
| JUnit 4 | مشغّل صغير في `tests/run.mjs` يكتشف `tests/**/*.test.mjs` |
| Truth | مساعدات في `tests/harness.mjs` (`assertEqual`, `assertDeepEqual`, `assertRejects`, …) |
| Robolectric | `createStorage(memoryStorage())` — بديل كامل لـ `localStorage` |
| SQLDelight في الذاكرة | نفس التخزين الوهمي لمخزن العلامات |
| MockWebServer | `fakeFetch(routes)` — `fetch` قابل للحقن في `src/data/api.js` |
| Turbine / اختبار Flow | قيم مُعادة + `onProgress` قابل للفحص |
| Kover | غير منطبق — استخدم `node --experimental-test-coverage` إن أردت |
| Espresso / Compose E2E | تحقق HTTP في `tests/http-smoke.mjs` (وأي متصفح لاحقًا) |

## التشغيل

```bash
npm test          # ٩٩ اختبارًا في ١١ ملفًا
npm run verify    # يبدأ الخادم ويزحف ٣١ مسارًا (شجرة الاستيراد كاملة)
npm run check     # الاثنان معًا
```

المشغّل يطبع ملخصًا لكل ملف، ويُرجع رمز خروج غير صفري عند أي فشل — مناسب لـ CI
دون أي خطوة تثبيت.

## التحقق عبر HTTP

`npm run verify` يبدأ `server.mjs` على منفذ حر ثم:

1. يتأكد أن `index.html` و`docs.html` و`404.html` تُخدَّم بأنواع صحيحة.
2. يتأكد من وجود `.nojekyll` ومن أن `404.html` يحوّل إلى جذر الموقع.
3. **يزحف شجرة الاستيراد** من نقطتي الدخول (`src/main.js` و`src/docs-viewer.js`)
   ويتأكد أن كل وحدة مستوردة تُخدَّم فعليًا بـ `text/javascript`.

هذا يكشف أخطر ما لا تكشفه اختبارات الوحدة: مسارًا نسبيًا مكسورًا — وهو تحديدًا
ما يفشل على GitHub Pages. (وقد كشف بالفعل خللًا حقيقيًا في الخادم أثناء البناء.)

يستخدم الزاحف `stdio: 'ignore'` عند تشغيل الخادم عمدًا: البيئات المقيّدة تمنع
الأنابيب المسماة، بينما التجاهل/التوريث يعمل في كل مكان.

## القواعد (كما هي)

* أسماء الاختبارات جمل تصف السلوك: `` `returns empty list when no bookmarks exist` ``.
* الترتيب Arrange / Act / Assert، مع التعليقات إن طال الاختبار.
* لا تختبر الدوال الخاصة مباشرة، ولا الوسم المُولَّد، ولا مكتبات الطرف الثالث.
* لا `setTimeout` داخل التحقق؛ استخدم حقنًا حتميًا.
