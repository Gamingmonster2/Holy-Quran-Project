# النشر على GitHub Pages — خطوة بخطوة

هذا التطبيق **ملفات ساكنة بالكامل** (HTML + CSS + JS) ولا يحتاج أي بناء، لذلك
GitHub Pages يشغّله كما هو. كل المسارات في المشروع نسبية (`./src/...`)، والتنقل
يعتمد على `#`، فيعمل الموقع داخل مسار فرعي مثل `username.github.io/repo/` بلا
أي تعديل.

---

## ١. قبل الرفع: تحقّق سريع

```bash
npm test        # ٩٠+ اختبارًا
npm run verify  # يبدأ الخادم ويزحف كل المسارات
```

الملفات التي **يجب** أن تكون في جذر المستودع (المستوى الأول):

```
index.html          ← صفحة التطبيق
docs.html           ← عارض التوثيق
404.html            ← يحوّل أي مسار خاطئ إلى التطبيق
.nojekyll           ← يمنع GitHub من معالجة الملفات بـ Jekyll (مهم)
src/                ← كل شيفرة التطبيق والأنماط
docs/               ← التوثيق
LICENSE  README.md  CONTRIBUTORS.md
```

`server.mjs` و `tests/` و `package.json` ليست ضرورية للموقع المنشور، لكن
إبقاءها مفيد لأنه يوثّق كيفية البناء والاختبار. لا تضرّ عمل الموقع.

---

## ٢. اختيار اسم المستودع (مهم للرابط)

اسم **المستودع** هو ما يظهر في الرابط:

```
https://<اسم-حسابك>.github.io/<اسم-المستودع>/
```

⚠️ **استخدم اسمًا بحروف لاتينية** مثل `quran-web` أو `quran` أو `quran-web-v1`.
الاسم العربي يُرمَّز في الرابط إلى `%D9%85%D9%88%D9%82%D8%B9%20...` فتصبح الروابط
طويلة وقبيحة، وكثير من الأدوات (الضغط، الرفع، CI) يتعامل معها بشكل سيئ.

### ⚠️ قاعدة عامة: أسماء الملفات بالإنجليزية دائمًا

**محتوى التطبيق عربي، لكن أسماء الملفات والمجلدات يجب أن تكون ASCII فقط**
(حروف إنجليزية، أرقام، `-` و `_` و `.`). لا عربية، ولا مسافات.

| ✅ صحيح | ❌ خطأ |
|---------|--------|
| `quran-web-v1/` | `موقع القران الكريم تجربه واحد/` |
| `src/data/api.js` | `src/data/واجهة.js` |
| `docs/DATA_SOURCES.md` | `docs/مصادر البيانات.md` |

السبب: المسار العربي يتحوّل عند الرفع أو الضغط إلى ترميز مثل
`%D9%85%D9%88%D9%82%D8%B9`، وهذا ما يُفشل الرفع أو يجعل الأرشيف غير قابل للفتح
على أنظمة أخرى.

المشروع مُتحقَّق منه آليًا: `npm test` يشمل اختبارًا (`tests/file-names.test.mjs`)
يفحص **كل** مسار في المشروع ويفشل إن وجد حرفًا غير إنجليزي أو مسافة أو رمزًا
ممنوعًا — بما في ذلك اسم مجلد المشروع نفسه. فإن ظهرت المشكلة مرة أخرى سيمسكها
الاختبار قبل الرفع.

> عند الرفع، ارفع **مجلد المشروع `quran-web-v1` فقط**. لا ترفع المجلد الأب
> (فهو يحتوي ملفات أخرى بأسماء عربية لا علاقة لها بالتطبيق).

## ٣. الرفع — الطريقة الأولى: من واجهة GitHub (بلا أوامر)

1. افتح <https://github.com/new>.
2. اكتب اسم المستودع (لاتيني)، واجعله **Public** (شرط لعمل Pages مجانًا)، ولا
   تُضف README ولا .gitignore (سنرفع ملفاتنا).
3. اضغط **Create repository**.
4. في الصفحة التالية اضغط **uploading an existing file**.
5. افتح مجلد `quran-web-v1`، ثم اسحب **محتوياته** (لا المجلد نفسه) إلى منطقة
   الرفع. على ويندوز: `Ctrl+A` ثم اسحب.
   * تأكد من ظهور `index.html` في الجذر، وأن مجلد `src` انتقل بكامله.
6. اكتب رسالة مثل `first version` ثم **Commit changes**.

> ملاحظة: واجهة الرفع في GitHub تُخفي الملفات التي تبدأ بنقطة أحيانًا. تأكد من
> رفع `.nojekyll` (وإن لم يظهر، استخدم **Add file → Create new file** وأنشئه
> بهذا الاسم واتركه فارغًا).
>
> ⚠️ إن فشل الرفع عبر الواجهة، فالأرجح أن ملفًا أو مجلدًا ما زال باسم غير
> إنجليزي — استخدم `git` (القسم التالي) أو شغّل `npm test` لمعرفة المسار المخالف.

## ٤. الرفع — الطريقة الثانية: Git (الأدق والأنصح)

من داخل مجلد المشروع:

```bash
git init
git add .
git commit -m "موقع القرآن الكريم — النسخة الأولى"
git branch -M main
git remote add origin https://github.com/<اسم-حسابك>/<اسم-المستودع>.git
git push -u origin main
```

Git يتعامل مع المسارات العربية والمسافات وأسماء الملفات التي تبدأ بنقطة بلا
مشاكل، ولهذا فهذه الطريقة أضمن.

عند أول `push` سيطلب GitHub تسجيل الدخول: استخدم **Personal Access Token** بدل
كلمة المرور (Settings → Developer settings → Tokens)، أو برنامج GitHub Desktop.

## ٥. تفعيل Pages

1. في المستودع: **Settings** → **Pages** (القائمة اليسرى).
2. تحت **Build and deployment** → **Source**: اختر **Deploy from a branch**.
3. **Branch**: اختر `main`، والمجلد **`/ (root)`**، ثم **Save**.
4. انتظر ١–٣ دقائق، ثم حدّث الصفحة. سيظهر رابطك:

```
https://<اسم-حسابك>.github.io/<اسم-المستودع>/
```

راقب تقدّم النشر في تبويب **Actions** إن تأخّر.

---

## ٦. ربط نطاق مخصّص (لاحقًا)

بعد أن تطمئن على الجودة:

1. **Settings → Pages → Custom domain**: اكتب نطاقك (مثال `quran.example.com`)
   ثم **Save**. سيُنشئ GitHub ملف `CNAME` في المستودع تلقائيًا — لا تحذفه.
2. في مزوّد النطاق أضف سجلات DNS:

   **إذا كان النطاق فرعيًا** (`quran.example.com`):
   ```
   Type:  CNAME
   Name:  quran
   Value: <اسم-حسابك>.github.io
   ```

   **إذا كان نطاقًا رئيسيًا** (`example.com`) — أضف أربع سجلات `A`:
   ```
   185.199.108.153
   185.199.109.153
   185.199.110.153
   185.199.111.153
   ```
   (وللـ IPv6 اختياريًا: `2606:50c0:8000::153` … `2606:50c0:8003::153`)

3. انتظر من ١٥ دقيقة إلى ٢٤ ساعة لانتشار DNS.
4. بعد أن يعمل النطاق، فعّل **Enforce HTTPS** (تحتاج شهادة TLS وقتًا للصدور).

## ٧. التحديث لاحقًا

```bash
git add .
git commit -m "تحسينات"
git push
```

كل `push` على `main` يُعيد النشر تلقائيًا خلال دقيقة أو دقيقتين. إن لم تظهر
التغييرات فورًا فحدّث الصفحة مع `Ctrl+F5` (المتصفح يخزّن الملفات).

## ٨. استكشاف الأخطاء

| ما تراه | السبب المرجّح | الحل |
|---------|----------------|------|
| صفحة بيضاء تمامًا | خطأ JavaScript | افتح أدوات المتصفح (`F12`) → Console واقرأ الخطأ |
| 404 على `src/main.js` | لم يُرفع مجلد `src` كاملًا | تأكد من وجود `src/main.js` في المستودع |
| تظهر الصفحة بلا تنسيق | لم يُرفع `src/styles/main.css` | تحقّق من المسار نفسه |
| النص القرآني لا يظهر | لا اتصال بالإنترنت، أو حجب لـ jsDelivr | جرّب شبكة أخرى؛ البيانات تُنزَّل من CDN |
| صور المصحف لا تظهر | مرآة الصور محجوبة | الإعدادات → «مصدر صور المصحف» وحدّد مرآة تعمل عندك |
| الصوت لا يعمل | سياسة التشغيل التلقائي في المتصفح | اضغط زر التشغيل بنفسك مرة واحدة |
| التغييرات لا تظهر | تخزين المتصفح | `Ctrl+F5`، أو افتح نافذة تصفّح خفي |

## ٩. تنبيهات مهمة

* **لا تعتمد على حركة مرور عالية على jsDelivr**: هي خدمة مجانية للمشاريع مفتوحة
  المصدر، وقد توقف الخدمة عن نطاق يستنزفها. إن كبر مشروعك، **استضف الملفات
  عندك** (انظر `DATA_SOURCES.md` → الاستضافة الذاتية) وحدّد المرآة من
  الإعدادات أو غيّر الثوابت في `src/data/api.js`.
* **رخصة الكود GPL-3.0**: المستودع المنشور يبقى مفتوح المصدر، وأي تعديل تنشره
  يجب أن ينشر معه الكود.
* **البيانات لأغراض غير تجارية** عمومًا (كل مصدر ورخصته). لا تضع إعلانات ولا
  مبيعات داخل التطبيق.
* **بديل احترافي**: لو أردت لاحقًا مصادر Quran Foundation الرسمية فستحتاج خادمًا
  خلفيًا (OAuth2 بمفتاح سري) — وهذا خارج نطاق موقع ساكن على Pages.

## ١٠. بديل اختياري: النشر عبر GitHub Actions

إن فضّلت التحكم الكامل بدل «Deploy from a branch»، اجعل
**Settings → Pages → Source = GitHub Actions** وأنشئ الملف
`.github/workflows/pages.yml`:

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: .
      - id: deployment
        uses: actions/deploy-pages@v4
```

هذا المشروع **لا يتضمن** هذا الملف افتراضيًا لتجنّب التعارض بين طريقتي النشر:
إن كان Source على «Deploy from a branch» فلا حاجة إليه.
